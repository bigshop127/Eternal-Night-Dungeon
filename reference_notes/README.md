## 固定起始畫面（`00_起始畫面.png`）

使用者 9/1 補充的**真實遊戲截圖**（不是來自 docx，是直接截圖分享的）：
「我每次腳本都會從這裡開始執行」——這張地城總覽圖是**每次跑腳本的固定起點**，
`engine.py` 主迴圈第一個要辨識、要能定位回去的畫面就是它。

畫面內容（供之後比對真實錄製截圖時參考）：
- 標題「永夜迷城（困難模式）」，右上角有「重置」鈕與倒數計時（重置後地圖節點內容會換）。
- 整張六角格地圖上**所有節點的圖示同時可見**（金色寶箱、多種怪物立於彩色光環平台上、
  一個像是獎勵轉盤縮圖的紫色平台圖示），玩家角色本人站在畫面中下方一塊亮起的格子上，
  應該就是目前所在位置／路徑起點。
  → 這點可能代表：節點類型也許不用走近或點開才知道，地圖總覽階段就能直接讀圖示分類，
  等真實錄製截圖進來要驗證這個猜測，不要現在就寫死進邏輯。
- 右下角有「獎勵／英靈／迷失的英魂／諾倫之心」四個入口鈕，左下角有說明卷軸與另一個徽章鈕，
  這些目前不確定是不是這次自動化流程要用到的東西，等錄製時使用者實際點過哪些才知道。

## 節點類型對照

- **寶箱**（`01_寶箱.png`）——金色寶箱圖示。**選擇之後還是要先進戰鬥**，打贏才能拿到寶箱獎勵，
  不是點了直接領獎勵。
- **戰鬥**（`02_戰鬥_石巨人.png` / `03_戰鬥_火巨人.png` / `04_戰鬥_紫法師.png`）——
  同一種節點類型的三種不同怪物外觀範例，敵人長相不同但都算「戰鬥」節點。
- **治癒**（`05_未確認_綠色小人.png` / `06_治癒_噴泉.png`）——同一種節點類型的兩種樣子
  （使用者已確認 05 也是治癒，不是復活）。

- **命運的契機**（`07_命運的契機_圖示.png`）——地圖上金色「?」圖示的節點（使用者 9/4 補充，非
  Word 文件來源，是真實遊戲截圖）。點選後跳出 2 張卡片，各自寫一段效果文字，玩家選一張。

  **決策規則（9/4 使用者確認，務必照這個規則寫進 `engine.py` 的決策表，不要自己推測）：**
  1. **凡卡片效果文字提到會「移除／替換」已獲得的英魂／英靈（即會讓玩家失去或替換掉已收集到的
     英魂）的選項，一律禁止選擇。**
     - 例：`08_命運的契機_選項A_回復vs替換英魂.png` 右邊卡片「...隨機更換1個已獲得的英魂」
       → 禁止。左邊卡片「我方所有上陣英靈回復最大生命的30%」（純回復、不動英魂）→ 可選。
     - 例：`09_命運的契機_選項B_升史詩vs英靈陣亡.png` 右邊卡片「隨機使我方1名英靈死亡，
       無法上陣...」→ 禁止（英靈死亡＝移除）。
  2. **唯一例外：「將已獲得的非史詩品質英魂更換為隨機史詩品質英魂」（品質升級成史詩）
     這個選項，即使技術上也是一種「更換」，一律選擇，不受規則1限制。**
     - 例：`09_命運的契機_選項B_升史詩vs英靈陣亡.png` 左邊卡片就是這個效果 → 一律選它
       （這張圖剛好同時示範規則1的禁止例＋規則2的例外，兩張卡都在同一張截圖裡）。
  3. **如果同一次跳出的所有選項都落在「禁止」範圍內（沒有規則2例外可選、也沒有純中性選項）：**
     - 不選任何卡片，直接關掉這個彈窗／畫面
     - 點擊右上角「重置」鈕（位置見 `10_地圖總覽_重置按鈕位置.png`）
     - 跳出「選擇層數」對話框後，選「第4層」＋難度「困難」，按「開始挑戰」重新開始整趟地城
       （見 `11_重置後選擇層數對話框.png`）

## 總覽的黃色圖釘（9/24 補充）

`12_overview_pins_0924.png`：使用者 9/24 提供的真實總覽截圖（1475×831，BlueStacks 範圍 1478×828）。
畫面上 **5 個黃色小人圖釘**（含 1 個頂端被畫面邊緣切掉一截的），是 `overview.py` 偵測圖釘的測試素材。

- 圖釘＝可選節點的標記，浮在節點上方、**會上下飄動（最大約 ±24px）**，所以只能用左右位置判斷鏡頭是否靜止。
- 節點要點的位置＝圖釘底端往下約 105px（參考尺度 818 高；你 9/20 錄製的 47/50 次點擊落在這附近）。
- 「命運的契機」的金色「?」顏色跟圖釘幾乎一樣，但比較矮、鉤子形（填充率 0.38 vs 圖釘 ≥0.46），
  `find_pins` 用高度／填充率／寬高比濾掉（`10_地圖總覽_重置按鈕位置.png` 是負面範例，不該有任何圖釘）。
- 已知：**另一隊（右下角法師那隊）身邊的節點常常沒有圖釘**（錄製裡 8/65/106 號點擊），還有英雄腳邊的寶箱也沒有
  （27/91/137）。這些自動選節點看不到，要靠使用者自己點，或之後再研究圖釘的出現規則。

`13_overview_reframed_0924.png`：使用者 9/24 重新框選之後的**實際範圍**（1475×834）。範圍上緣比遊戲畫面高了 2px（多包進
BlueStacks 工具列的 2 排像素）。這個小誤差讓「總覽」標題列的距離從 7.0 跳到 14.4（門檻 12），輔助器整個認不得總覽——
所以區域樣板比對現在會在 ±6px 內找最像的位置（`vision_state.BOX_SHIFTS`）。這張圖是那個回歸的測試素材。

**使用者 9/24 補充的遊戲規則**：畫面分左右兩邊，左右兩邊各自派出不同隊伍進攻；**閃爍的黃色圖釘＝左邊或右邊下一步能選擇的
節點；沒有圖釘的節點就是還沒走到**（所以「沒圖釘」不是輔助器看不到，是還不能選）。圖釘會閃爍／上下浮動，規劃器因此
替每個圖釘記軌跡：熄滅時不會被當成「沒圖釘」而去拖地圖。

## 9/25 更正與新畫面（使用者貼的 4 張圖，`17~20_*_0925.png`）

**更正上面「沒圖釘的節點就是還沒走到」**：使用者 9/25 說，遊戲**有時本來就不顯示圖釘**（例如左隊卡在觸發裝置、把畫面往下拉到右隊那邊時），

再找鄰接的節點（見 `README.md` 的「沒有圖釘也能點」）。
