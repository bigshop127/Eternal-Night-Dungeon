> 2026-11-22 從 `C:\CC AI Agent\eternal_night_dungeon` 搬到 `C:\Eternal-Night-Dungeon`，獨立 repo `bigshop127/Eternal-Night-Dungeon`（私人）。

跟水果 2048 輔助器（`C:\Fruit-Assist-bot`）同一種用法：一個永遠置頂的小面板停在**螢幕右邊**，
模擬器留在左邊。你先框出「模擬器裡的遊戲畫面」，之後所有辨識、點擊、錄製都**只發生在這個範圍裡**，
範圍外的東西（桌面、別的視窗、模擬器的側邊工具列）程式完全看不到、也點不到。

## 啟動

雙擊桌面的「**永夜迷城輔助器**」捷徑。需要 Python 3.9 以上，第一次執行會自動裝套件。
也可以直接 `python app.py`。

## 背景操控（11/22 起預設；`adb_io.py`）

跟水果 2048 輔助器的背景模式一樣：**畫面用 adb 從模擬器裡面抓、點擊與拖地圖用 adb 送進模擬器**，完全不碰滑鼠、不看桌面。
模擬器被別的視窗蓋住、甚至縮到最小都照跑，你可以同時用電腦做別的事。面板底下的「操控：背景 adb／前景滑鼠」按鈕切換，設定存在
`config.json` 的 `control_mode`（`adb`／`screen`）。

* 模擬器：`adb_serial`（預設 `127.0.0.1:5555`＝BlueStacks「1」）。連不上就自動找開著 ADB 的那台；好幾台都開著時挑畫面認得出來的那台。
  BlueStacks 要在「設定 → 進階 → Android 偵錯橋（ADB）」打開（這台 11/21 水果 2048 時已經開了）。
* 背景模式不用框選：畫面是模擬器整個螢幕（1280×720）縮成你上次框選的範圍大小（1161×654），樣板與各種像素門檻都照舊。
* 緊急停止 `F8` 照樣有效（在任何程式裡按都可以）。錄製要記你的滑鼠點擊，只有前景模式能用。
* 11/22 實測：BlueStacks 縮到最小時 adb 截圖仍是即時畫面，一張約 0.15 秒，輔助器每輪約 0.16 秒。**還沒在地城裡實際跑過一輪**。

## 換邊大步快拖＋換邊記憶（11/22）

你 11/22 的要求：「一邊的路線走完一個階段之後，要回去另外一邊的速度、幅度都可以加大、加快」。11/08 那輪記錄：4 次換邊各拖 4~6 下、
每下約 3.2 秒；第 4 段左隊點完最後的裝置後連拖 23 下沒找到右隊（右隊在更右邊，往右下斜兩下不夠右，之後只往正下、正上找），你手動接手。

* **什麼時候算換邊**：照路線走時，要找的不是剛走完一步的那隊（例如左隊碰到裝置、換右隊）；路線走完之後，另一隊點了裝置在等它。
  找同一隊（鏡頭只是沒對準）照舊小步慢找。
* **大步**：每一步上下拖 1.75 倍（`switch_scale`）、左右拖 √1.75≈1.32 倍——兩隊左右距離大致固定，左右放太大會一下拖過頭。
  走法：往那隊那側斜拖 2 大步 → 往下 4 → 回頭往上 8 → 萬一認反往另一側 3 → 往下 3。起訖點都避開標題列、「f」、下面兩排圖示。
* **快**：換邊時兩次動作間隔 0.9 秒（`switch_interval`，平常 `map_interval` 2.5 秒），每下拖 0.35 秒（平常 0.5）。找到之後點節點也用 0.9 秒間隔。
* **換邊記憶**（`switch_memory.json`，`switch_memory: true`）：地圖固定、鏡頭每次都停在剛行動那隊身上，所以同一個換邊點
  （「左隊走完第 24 步 → 找右隊第 14 步」這種代號）每一輪看到的畫面一樣。第一次大步找到後記下總共拖了多遠，
  **下一輪直接拆成最少幾下一口氣拖過去**。照記憶拖完沒看到 → 先拖回原點再照大步走法找，找到就更新記憶；最後還是找不到、停手叫你時，
  那筆記憶刪掉，下一輪重新學。記憶亂了就刪掉 `switch_memory.json`。
* **驗證**（全離線，`test_switch.py`）：假地圖重現 11/08 第 4 段的情況——舊走法拖 23 次停手（跟真的一樣），新走法 4 次就找到右隊、
  點了路線要的寶箱；近一點的 3 種位置也不會拖過頭；第一輪繞遠路要 14 次的情況，第二輪照記憶 2 次；錯的記憶會自己修正；
  adb 截圖／座標換算／點擊與拖曳指令（假 adb）。**真遊戲上 1.75 倍會不會太大要實機看**——太大就把 `config.json` 的 `switch_scale` 調小
  （例如 1.5），太慢就把 `switch_interval` 調小。

路線全貌（走的順序、4 個換邊點、每段示意圖與標號截圖）：claude.ai Artifact「永夜迷城路線圖」`F1RGmZVGhvMYnnCSn4jPuM`。

模擬器視窗要留出右邊約 400px 給面板（1920 寬的螢幕，模擬器寬度抓 1500 以內）。
面板蓋到框選範圍的話，程式會警告並拒絕自動操控／錄製——蓋住的話點擊會點到面板自己，
擷取到的畫面也會被面板汙染。

## 使用流程

### ① 框選畫面範圍（一次）

按「① 框選畫面範圍」→ 整個桌面變暗，**沿著模擬器裡的遊戲畫面拖曳一個框**。
框好之後不會馬上結束：方向鍵微調位置（Shift＝改大小、Ctrl＝一次 10px），**Enter 確定**，
或直接重新拖曳重框，Esc 取消。面板全程浮在遮罩上面。

框到的如果剛好是一個模擬器視窗，程式會順便**鎖定那個視窗**：之後把視窗搬到別處，範圍會跟著走，
不用重框。**視窗大小變了就不會再自動接**，會停手並請你重框——大小一變，範圍裡每個東西的相對
位置都變了，硬套原本的位移只會看錯、點錯。

### ② 標記畫面（每種畫面教一次）

遊戲停在某個畫面時按「② 標記畫面」：

1. 幫這個畫面取名（例如「地圖總覽」「戰鬥」「獎勵輪盤」）。
2. 選動作：
   * **看到這個畫面就點一下**——在圖上點出要點的位置（會存成範圍內的比例，換視窗大小/位置都還準）。
   * **只辨識、不動作**——戰鬥動畫等，等它自己過去。
3. 存檔。

同一個名字可以標很多次（同一個畫面會有不同的樣子，例如不同怪物的戰鬥畫面），標越多越準。
太像既有樣板的畫面不會重複收，但動作一律更新。選既有名稱會帶出原本的動作；也可以在這裡刪除整個狀態。

### ▶ 開始自動

面板上方會即時顯示「程式現在認為這是什麼畫面」與預覽（就是它實際看到的範圍，紅色十字＝這個畫面
會點的位置）。認得出來、而且有設「點擊」動作的畫面，按「▶ 開始自動」之後程式就會自己點。

* **隨時停止**：按 `F8`（不用切回面板）、或按「■ 停止自動」、或按「暫停」。
* 每次啟動程式，自動操控一定是關的，要人工按一次才會動。

它會**自己停手**的情況（不會亂點）：

| 情況 | 說明 |
|---|---|
| 連續認不得畫面超過 90 秒 | 可能有沒教過的畫面 |
| 在同一個畫面連點 4 次都沒變化 | 多半是視窗被擋住了 |
| 點擊目標最上層不是遊戲 | 輔助器自己的視窗、或別的程式（瀏覽器、別的遊戲）蓋在模擬器上面；點下去只會點到它們。判斷別的程式要靠「框選時鎖定了視窗」 |
| 送不出滑鼠輸入 | 模擬器若以系統管理員身分執行，輔助器也要用系統管理員身分開 |
| 抓不到畫面 | — |

視窗被縮小、被關掉、或大小變了的時候，程式安靜等待（自動操控維持開著），還原後自動接回去。

使用者按著滑鼠左／右鍵時（例如正在拖地圖），這一輪不點；不算重試、不會停手，放開後畫面沒變才會點。

### ● 錄製

想讓 Claude 看你怎麼玩的時候：按「● 開始錄製」，照平常玩法點就好，玩完按 `F8` 或「■ 停止錄製」。
只記**框選範圍內**、而且最上層真的是遊戲的真人點擊（程式自己送的點擊、被別的視窗蓋住的點擊都不算），存到 `sessions/<時間>/`：

* `before_NNN.png` / `after_NNN.png`：每次點擊前、點擊後 0.7 秒的畫面（範圍內，不是整個螢幕）
* `clicks.json`：每次點擊的時間、螢幕座標、範圍內座標、**範圍內比例**（可以直接當規則座標用）

錄製中不能自動操控、不能重框範圍。

### 總覽自動化怎麼運作（`overview.py`）

**畫面分左右兩邊，兩邊各派一隊進攻，用英雄的長相分辨：野蠻人（光著上身、金色法杖）＝左隊，法師（藍色披風、青色寶珠法杖）＝右隊。
閃爍的黃色小人圖釘＝該隊下一步能選的節點，沒有圖釘的節點就是還沒走到**（使用者 9/24 說明）。
用你 9/20 那一輪錄製驗證過：你在總覽點節點的 46 次裡，絕大多數點在最近圖釘正下方（圖釘底端往下約 105px）。做法：

1. **找圖釘**：黃色瘦長小人（高 41~58、填充率 ≥ 0.46）。金色「？」（命運的契機）顏色一樣但較矮、鉤子形，濾掉；
   被頂端標題列蓋住一半的圖釘也認（只看窄長）；右下角介面上的黃色不算。
   **「閃爍」＝上下浮動**：9/24 實機連拍 8 秒 219 幀，4 個圖釘每一幀都在、只是底端上下動 23~27px、週期約 1.5 秒，
   不會熄滅。規劃器仍替每個圖釘記軌跡當保險：最近 1.2 秒內看到過才算「現在有」，2 秒都沒看到任何圖釘才算真的沒有。
2. **認節點種類**：切圖釘下方的小圖，跟 `overview_assets/nodes/` 的樣板比（最近鄰，留一驗證 39/40）：
   寶箱／治療符文（含藍色泉水）／觸發裝置／怪物。離所有樣板太遠＝「認不得」＝**不自動點**（例如命運的契機）。
   **藍色泉水一律視作治療**（使用者 9/25：「一律視作治癒，一定要選」；原本我分成「復活」排在怪物後面，
   所以 9/25 log 裡「看到 2 個節點：復活、怪物」它選了怪物）。舊樣板檔載入時 `KIND_ALIAS` 會把 revive 換成 heal。
3. **挑一個**（優先序可改）：**寶箱 → 治療 → 怪物 → 觸發裝置**（使用者說「寶箱、治療為主」）；同一層取畫面最上面的。
   * 寶箱盡可能都選（使用者 9/24 的規則）。
   * **治療排在怪物前面**：治療是多選一的其中一個選項，選了旁邊的怪物，這條路的治療就沒了。
     （9/24 晚使用者回報「右隊遇到治療卻選了旁邊的戰鬥」＝我原本把怪物排在治療前面，兩隊都打過了也一樣，已修正。）
   * **治療的閘門**：治療兩隊同時回血，所以選治療前要「另一隊」自上次治療以來至少打過一場（勝利畫面記場數）。
     沒輪到時**不會降級去點同一個岔路的怪物**，而是**改點另一隊的怪物讓它先打一場**，這一隊的治療留著；
     另一隊沒有怪物可打（或隊伍分不出來、不確定）就直接點治療，不能為了等而把治療放掉。面板與動作記錄會註明。
     輔助器在一輪遊戲中途才開的話，場數從 0 開始算——最壞就是讓另一隊多打一場，不會放掉治療。
   * 觸發裝置一按就進下一階段（已收集的寶石消失），所以放最後（這條是我補的假設，使用者沒明說）。
4. **左右隊怎麼判斷**：點節點的那一刻用 `HeroFinder`（`overview_assets/heroes/` 兩張英雄小圖做多尺度模板比對，約 0.35 秒）
   找英雄，圖釘離哪位英雄近就算哪隊；只找到一位而且圖釘離它太遠、或一位都沒找到，就退回**畫面左半＝左隊、右半＝右隊**。
   點下去之後等到「勝利」畫面出現，那隊記一場；點治療就兩隊都歸零。面板訊息會顯示「自上次治療：左隊 N 場、右隊 M 場」，
   動作記錄會寫「（右隊）」與「戰鬥勝利：右隊記一場」。**英雄偵測的限度**（用 55 張錄製總覽驗證）：37 張至少找到一位、
   6 張兩位都找到、18 張找不到（姿勢動畫、金色塵土特效、英雄不在畫面內）；目視 18 張沒看到誤認。找不到就走左右半邊的退路。
   分不出隊（side 未知）時不記場數。**擋治療用的隊伍判斷更嚴格**（`side_of_sure`）：英雄判斷跟畫面左右半邊要一致才算，
   不一致（畫面正中央那一欄、只偵測到一位英雄）就當不確定＝不擋治療，避免把同一個岔路的兩個選項誤分到不同隊、點到旁邊的怪物。
   預覽上有治療可選時，每個節點會標「怪物·左」「治療·右」。點擊的動作記錄會寫下當時看到的節點與場數，並同步寫進 `app_log.txt`。
5. **沒有圖釘也能點：找隊伍前面的節點**（9/25 新增，`overview.find_platforms／find_candidates／adjacent_nodes`）。
   **使用者 9/25 更正了我對圖釘的理解**：圖釘並不是「能點的節點」的唯一標記——遊戲有時本來就不顯示圖釘（例如左隊卡在觸發裝置、
   把畫面拉到右隊那邊時），但隊伍前面的兩個戰鬥照樣能點。所以「連 2 秒沒圖釘」不再等於「沒得選」，改成：

## 辨識原理

整個範圍縮成 96×96 小圖，各色版減掉自己的平均值（所以整體亮度變化不影響），跟每張樣板算平均
像素差，取最近的。**寧可說不認得也不亂猜**：

* 距離超過門檻（18）→ 不認得。
* 第二名的狀態太接近（差距 < 2）→ 不認得。
* **內容太少的畫面（純黑、純色的轉場）→ 不認得。**減掉平均值之後，純色畫面的特徵幾乎是零向量，
  它跟任何對比不高的樣板的距離都只等於那張樣板自己的內容量，可能剛好小於門檻而被誤認。
  所以距離另外不能超過兩邊內容量較大者的一半（同一個畫面遇到亮度／雜訊變化，這個比值實測 < 0.1；
  純色畫面對任何樣板都是 1.0）。純黑畫面要當成一個狀態的話，把它標成一個狀態就行。
* 連續兩次讀到同一個狀態才採信（擋掉轉場動畫）。

**框選範圍的小誤差（位移容忍）**：區域樣板只有一小塊、邊緣對比強，特別怕位移——9/24 你重新框選的範圍上緣高了 2px
（多包了 BlueStacks 工具列），總覽標題列的距離從 7.0 跳到 14.4（門檻 12），整個輔助器認不得總覽、什麼都不做。
所以區域樣板比對時會在 ±6px 內（`BOX_SHIFTS`，9/25 起間隔 2px）找最像的位置；平常只試「不位移」和「上次贏的位移」，
認不得才做完整搜尋（限頻，穩態約 15ms）；但「差一點」的畫面（不位移的距離在該組門檻 2 倍內，`BOX_NEAR`）不受限頻、每次都完整搜尋。
量過對鑑別力沒影響（別的畫面對總覽標題列最小距離仍 ≥ 17.1，對「提示框」文字區 ≥ 12.85）。
面板顯示「認不得這個畫面」但遊戲明明在總覽時，先檢查範圍上緣有沒有多包到工具列——現在 ±5px 內都不會有事，更大就重框。

**區域樣板、後備狀態、專用門檻**（`vision_state.py`，預設都不用，只有 `tools/seed_templates.py` 建的樣板會用）：

* **區域樣板（box）**：只拿畫面上某一塊固定區域比對，不受其他地方影響。彈窗本體不透明，只比彈窗就不會被
  背後一直變動的地圖拖累；地城總覽整張每次都不同，只能靠不變的標題列認。
* **後備狀態（fallback）**：只有其他所有畫面都認不得時才輪到它。「總覽」用它——彈窗疊在總覽上時標題列也在，
  如果讓它跟大家一起比，彈窗會被誤判成總覽（實測彈窗跟總覽的標題列距離只有 0.0～0.2）。
  副作用：沒教過的新彈窗只要標題列是亮的，會被當成總覽而安靜等待——看到面板停在「總覽」但它沒動作，
  就是有新畫面要教。
* **專用門檻（label_tolerance）**：比全域(18)更嚴，只能收緊不能放寬。「提示框」設 2.0：彈窗文字區實測三次
  出現距離都是 0.0，換了別段文字的合成確認框 ≥ 12——所以同外框的別種確認框（例如「確定要重置？」）
  會被拒絕、不會被自動按「確定」。

## 更新樣板（有新的錄製時）

錄製只是原始素材。要讓輔助器認得新畫面／新規則：

**總覽的節點樣板**另外用 `python tools/build_overview_assets.py sessions/<時間> [--dry-run]` 建
（`overview_assets/nodes/`＋把「總覽」「起始畫面」規則設成自動選節點，先備份 `rules.json`）。每個節點種類
對應的錄製點擊序號寫在該檔的 `NODE_KINDS`（看點完之後彈窗的標題認的）；新錄一輪、新種類補一行重跑即可。

1. 在 `sessions/<時間>/` 放一個 `labels.json`（`{"labels": {"幀編號": "畫面名稱", ...}}`，看 `before_NNN.png` 標）。
2. 需要新畫面種類的話，在 `tools/seed_templates.py` 的 `SPEC` 加一行（點哪裡、要不要區域比對、要不要後備／專用門檻）。
3. `python tools/seed_templates.py sessions/<時間> --dry-run` 看摘要，沒問題去掉 `--dry-run`（會先自動備份到 `backup/`）。
4. `python tools/replay_session.py sessions/<時間> --cv` 交叉驗證、`--engine` 用真引擎（假時鐘＋假點擊）模擬整輪。

也可以直接用面板的「② 標記畫面」教（只能整張比對）。你自己教的畫面，重跑 `seed_templates.py` 不會動到。

python test_engine.py     # 引擎邏輯，全假資料，不開視窗
python test_overview.py   # 總覽自動化：圖釘/分類/優先序/規劃器（含閃爍）/引擎整合（假擷取、假點擊、假拖曳）；有錄製資料時另跑真實畫面回歸與框選位移回歸

python test_recorder.py   # 真的掛滑鼠鉤子，只點自己開的假視窗（每一下之前先確認座標底下是假視窗）

**9/27 更正**：`replay_session.py --engine` 以前只換掉了「點擊」、沒換掉「拖地圖」——總覽決定拖地圖時會送出**真的滑鼠拖曳**
到桌面左上角那一帶（9/27 跑的時候拖了 2 下）。已修：點擊、拖曳、防護、滑鼠狀態全部換成假的，也不再存 `debug_frames/`。

## 維護筆記

**Tk 物件只准在主執行緒回收。**對話框、遮罩關掉之後留下的 `StringVar`／`PhotoImage` 會互相參照成循環
垃圾，等循環 GC 來收；而循環 GC 是「誰剛好在配置記憶體就在誰的執行緒觸發」——背景偵測執行緒每輪都在
配置畫面陣列，常常就是它。`Variable.__del__` 在背景執行緒呼叫 Tcl 會卡住等主執行緒，最壞情況跟 UI 執行緒
持有的 lock 互等成死結（端到端測試實際抓到：背景偵測凍住好幾秒）。所以 `AssistApp` 一開始 `gc.disable()`，
改由 `_pump` 每 3 秒在主執行緒手動 `gc.collect()`；`test_app.py` 第 11 節有回歸測試（關掉修法就會紅）。

**用 PIL 的 `ImageGrab` 截圖驗證畫面會漏掉面板**——面板有透明度（layered window），`ImageGrab` 不抓這類視窗；
`mss` 抓得到，所以程式擷取範圍時面板若蓋在範圍上一定會被拍進去。這也是為什麼面板蓋住範圍時要擋。

**啟動 pythonw 時 `-WindowStyle` 一定要明確寫 `Normal`。**省略不寫會繼承桌面捷徑的最小化狀態
（捷徑本身是 `WindowStyle=7` 用來壓掉 PowerShell 黑視窗），輔助器一開就縮在工作列；寫 `Hidden` 更慘，
程式在跑但完全看不到視窗。
